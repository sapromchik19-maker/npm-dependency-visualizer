# Визуализатор зависимостей npm

Практическая работа №2 по дисциплине «Конфигурационное управление».

**Вариант №4.**

## Описание

Консольное приложение на Python для анализа и визуализации зависимостей npm-пакетов.

Программа получает зависимости из npm Registry, строит граф с помощью BFS,
определяет порядок загрузки зависимостей и визуализирует результат.

Поддерживаются вывод графа в формате SVG и отображение ASCII-дерева.

Для получения зависимостей используются средства стандартной библиотеки Python.

## Требования

- Python 3.11 или новее.
- Java, доступная через команду `java`.
- PlantUML в виде файла `plantuml.jar` в корне проекта.
- Интернет для получения зависимостей из npm Registry.

PlantUML можно скачать с официального сайта:
https://plantuml.com/download

Файл `plantuml.jar` не включён в Git-репозиторий.
Его необходимо скачать отдельно перед запуском визуализации.

## Параметры командной строки

- `--package` — имя анализируемого npm-пакета.
- `--repository` — URL npm Registry или путь к JSON-файлу.
- `--version` — версия пакета.
- `--output` — путь к выходному SVG-файлу.
- `--test-mode` — использование тестового JSON-репозитория.
- `--ascii` — вывод зависимостей в виде ASCII-дерева.
- `--load-order` — вывод порядка загрузки зависимостей.

Параметры `--package`, `--repository`, `--version` и `--output` обязательны.

## Запуск программы

Откройте PowerShell в корневой папке проекта.

Пример запуска для `is-odd@3.0.1`:

```powershell
python -m src.main --package is-odd `
    --repository https://registry.npmjs.org `
    --version 3.0.1 `
    --output graph.svg `
    --ascii
```

В Windows также можно использовать `run.bat`:

```powershell
.\run.bat --package is-odd `
    --repository https://registry.npmjs.org `
    --version 3.0.1 `
    --output graph.svg `
    --ascii
```

Перенос команд с помощью обратной кавычки предназначен для PowerShell.

## Этап 1. Настройка командной строки

Реализован интерфейс командной строки.

Программа принимает параметры анализа, проверяет их корректность
и обрабатывает ошибки пользовательского ввода.

Предусмотрены режим тестового репозитория, ASCII-вывод
и указание выходного SVG-файла.

## Этап 2. Получение прямых зависимостей

Реализовано получение прямых зависимостей выбранной версии npm-пакета.

Данные запрашиваются через URL npm Registry.

Для сетевых запросов используется стандартная библиотека Python.
Готовые библиотеки для получения зависимостей не используются.

Обрабатываются ошибки HTTP, подключения и некорректных ответов сервера.

## Этап 3. Построение графа зависимостей

Реализован обход графа в ширину (BFS) без рекурсии.

Возможности:

- Получение прямых и транзитивных зависимостей.
- Обработка повторяющихся зависимостей.
- Обработка циклических графов.
- Работа с тестовым JSON-репозиторием.
- Работа с реальными npm-пакетами.
- Выбор версий для точных требований и диапазонов `^` и `~`.

Поддержка npm SemVer ограничена.
Некоторые сложные диапазоны версий могут не обрабатываться.

### Тестовый режим

```powershell
python -m src.main --package A `
    --repository data/test_graph.json `
    --version 1.0.0 `
    --output graph.svg `
    --test-mode
```

В тестовом репозитории пакеты называются заглавными латинскими буквами.

## Этап 4. Порядок загрузки зависимостей

Реализовано определение порядка загрузки зависимостей
с помощью топологической сортировки графа.

Зависимости располагаются перед пакетами, которые их используют.

Режим включается параметром `--load-order`.

### Пример для npm

```powershell
python -m src.main --package is-odd `
    --repository https://registry.npmjs.org `
    --version 3.0.1 `
    --output graph.svg `
    --load-order
```

Результат:

```text
Порядок загрузки:
1. is-number@6.0.0
2. is-odd@3.0.1
```

### Пример для тестового репозитория

```powershell
python -m src.main --package A `
    --repository data/acyclic_graph.json `
    --version 1.0.0 `
    --output graph.svg `
    --test-mode `
    --load-order
```

Пример результата:

```text
Порядок загрузки:
D -> E -> B -> C -> A
```

### Циклические зависимости

Если граф содержит цикл, программа сообщает,
что полный топологический порядок определить невозможно.

Пример сообщения:

```text
Ошибка порядка загрузки:
Обнаружен цикл: порядок загрузки определить нельзя
```

Построение самого графа при этом поддерживает циклические зависимости.

## Этап 5. Визуализация графа зависимостей

Реализована визуализация графа с помощью PlantUML.

Программа создаёт текстовое описание графа на языке PlantUML
и передаёт его PlantUML для формирования SVG-изображения.

Параметр `--ascii` включает текстовое представление зависимостей.

### Пример 1. is-odd@3.0.1

```powershell
python -m src.main --package is-odd `
    --repository https://registry.npmjs.org `
    --version 3.0.1 `
    --output is_odd.svg `
    --ascii
```

ASCII-дерево:

```text
is-odd@3.0.1
`-- is-number@6.0.0
```

Выходной файл: `is_odd.svg`.

### Пример 2. is-even@1.0.0

```powershell
python -m src.main --package is-even `
    --repository https://registry.npmjs.org `
    --version 1.0.0 `
    --output is_even.svg `
    --ascii
```

ASCII-дерево:

```text
is-even@1.0.0
`-- is-odd@0.1.2
    `-- is-number@3.0.0
        `-- kind-of@3.2.2
            `-- is-buffer@1.1.6
```

Выходной файл: `is_even.svg`.

### Пример 3. is-number@6.0.0

```powershell
python -m src.main --package is-number `
    --repository https://registry.npmjs.org `
    --version 6.0.0 `
    --output is_number.svg `
    --ascii
```

ASCII-дерево:

```text
is-number@6.0.0
```

Пакет не имеет прямых зависимостей.

Выходной файл: `is_number.svg`.

## Сравнение с npm

Для сравнения был установлен пакет `is-even@1.0.0`.

Использовалась команда:

```powershell
npm ls --all
```

Имена и версии обнаруженных пакетов совпали.

При этом в выводе npm присутствует дополнительная связь
между `is-even@1.0.0` и `is-number@3.0.0`,
которой нет в построенном программой графе.

Причина расхождения требует дополнительной проверки.

npm показывает дерево установленных зависимостей.
Разработанная программа строит граф по метаданным npm Registry.

Также реализация разрешения версий поддерживает
не все возможности npm SemVer.

- Не более 7 аргументов функции.
- Цикломатическая сложность не более 10.
